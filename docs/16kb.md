# 16 KB page alignment

Builds apply the published `io.github.supermonster003.autojs6-native-alignment` plugin at the
version declared in `settings.gradle.kts`; prefer the latest release. Every assembled APK
is checked and reports are written to `app/build/reports/native-alignment/`.
Use `:app:verifyNativePageAlignment` to recheck existing artifacts.

The gate enforces ELF PT_LOAD alignment for arm64-v8a and x86_64. Uncompressed `.so` entries also require 16 KB ZIP alignment. Third-party 32-bit alignment is advisory.

Every native dependency or toolchain upgrade must pass the gate again. Static alignment
does not prove runtime behavior: test on a device reporting `getconf PAGE_SIZE = 16384`
with compatibility mode disabled. No `android:pageSizeCompat` override is permitted.

中文: 构建门禁检查全部产物并输出 JSON 报告. 原生依赖或工具链升级后必须重新校验,
且需在页大小为 16384 的设备上关闭兼容模式后执行运行时验证.

[Deployment and device acceptance matrix](https://github.com/SuperMonster003/AutoJs6/blob/master/docs/dev/page-size-16kb-roadmap.md)

Rapid OCR uses Maven ONNX Runtime 1.21.1 and a private OpenCV 4.8.0: `libRapidOcr.so`
statically links the core and imgproc libraries of the official OpenCV Android SDK
(TBB parallel backend, no OpenMP). The former OpenCV Mobile / static OpenMP combination
aborts when Paddle Lite and Rapid are loaded in the same user APK, so OpenMP must not return.
`-fvisibility=hidden`, `-Wl,--exclude-libs,ALL` and `src/main/cpp/RapidOcr.map` keep every
OpenCV symbol local; only `JNI_OnLoad`, `JNI_OnUnload` and the `Java_*` methods are exported.
The APK no longer ships `libopencv_java4.so`, and a user APK can include another OpenCV
version for images (the AutoJs6 OpenCV plugin) next to this engine.
`libs/opencv-android-sdk-4.8.0.provenance.json` pins the SDK archive, the upstream commit,
the upstream compiler and every static library per ABI; the build verifies both before
linking. To change the OpenCV version, download the new SDK, run
`tools/opencv/opencv_sdk_provenance.py`, update `RAPID_OCR_OPENCV_VERSION`, then rebuild and
verify on devices. Check with `llvm-readelf -d` (no `libopencv_java4.so` in `NEEDED`) and
`llvm-readelf --dyn-syms` (no `cv::` symbols).

ABI packaging: the app and plugin metadata include `arm64-v8a`, `armeabi-v7a`,
`x86`, and `x86_64`, with one APK per ABI and a four-ABI universal APK.
The SDK already builds `libRapidOcr.so` for all four ABIs, using matching slices
from ONNX Runtime 1.21.1 and the OpenCV Android SDK static libraries. Its existing NDK 28.2
`c++_shared` configuration supplies the C++ runtime for each ABI; no extra
prebuilt runtime is needed. After changing the ABI list, run `:app:assembleRelease`
and `:app:verifyNativePageAlignment`, then verify model loading and OCR on the
new target ABI.
